# SEO-аудит публичного сайта — 1 сентября 2026

## Область проверки

Проверены все 30 URL из публичного `sitemap.xml`: серверный HTML, `<title>`, `meta[name="description"]`, Open Graph и Twitter Card. Дополнительно проверены canonical slug компании «Стерео Пикник», общая Nuxt-конфигурация, runtime config, CMS settings, SEO-поля динамических сущностей и production build.

## Состояние live-сайта до деплоя правок

- 29 URL из sitemap отвечают `200`, `/companies/stereopiknik` ошибочно отвечает `404`.
- Ошибочный `/companies/stereo-piknik` отвечает `200`, хотя не должен быть отдельной страницей.
- Один sitemap URL не имеет title и description из-за ответа `404`.
- Один description повторяется на 9 страницах: `Интервью с основателями бизнеса`.
- 29 descriptions короче 120 символов; trademark description длиннее 165 символов.
- Title-дублей в текущем sitemap нет.
- На доступных страницах обычные, Open Graph и Twitter title/description синхронизированы.

## Что изменено

### Логика до исправления

- Статические разделы брали SEO из CMS settings, а fallback-тексты были продублированы в API и Vue-страницах.
- Динамические страницы механически собирали `Название — siteName`, после чего общий composable мог ещё раз обработать тот же title.
- Карточки компаний и предпринимателей при пустых `metaDesc` получали один общий description.
- Статьи, интервью и рилсы использовали короткий подзаголовок или общий description сайта без доведения до самостоятельного поискового сниппета.
- Runtime fallback `SITE_DESCRIPTION` содержал старую общую фразу.

### Логика после исправления

- Единственный SEO-бренд: `МАРШРУТ ПОСТРОЕН МЕДИАГИД`.
- Общий SEO-composable нормализует регистр бренда и синхронно устанавливает обычные, Open Graph и Twitter метатеги.
- Повторяющиеся сегменты title удаляются; бренд добавляется только если итоговый title не длиннее 70 символов. Длинный содержательный title остаётся без механической приписки.
- Статические значения собраны в одном реестре; CMS остаётся источником данных, а миграция синхронизирует существующие настройки с утверждёнными текстами.
- Динамические title/description строятся из фактических полей сущности: имени и роли героя, типа и владельца компании, заголовка, подзаголовка и участника материала.
- Description очищается от HTML, расширяется фактами и ограничивается диапазоном около 120–165 символов.
- Миграция возвращает компании canonical slug `stereopiknik`; ошибочный `stereo-piknik` после деплоя не остаётся второй индексируемой страницей.
- Schema.org получает тот же нормализованный description, что и метатеги.

## Проверки

- `npm run lint`
- `npm run typecheck`
- `npm run test`
- `npm run build`
- `git diff --check`
- live crawl публичного sitemap и всех входящих в него URL
- расчёт итоговых динамических метатегов на фактических данных публичного API

Полный локальный SSR crawl собранного приложения требует доступной PostgreSQL. В текущем окружении `localhost:5433` недоступен, поэтому Nitro возвращает `500` до выполнения страницы. Production build и SSR-компиляция проходят; после деплоя миграции требуется повторный crawl server HTML.
