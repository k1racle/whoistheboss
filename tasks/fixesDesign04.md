# fixesDesign04 — четвёртая волна правок от дизайнера

Назначение: документ фиксирует исследование и реализацию четвёртой волны правок публичного сайта и админки. Владелец подтвердил выполнение всей волны сообщением «вперед».

## Правила работы

Статусы задач:

- `new` — задача исследована и ожидает подтверждения перед реализацией.
- `approved` — владелец подтвердил решение и назначил задачу в работу.
- `in-progress` — правка выполняется прямо сейчас.
- `done` — код изменён, `npm run lint` и `npm run typecheck` проходят.
- `verified` — владелец или дизайнер проверил результат визуально.
- `waiting-owner` — для продолжения требуется решение владельца.

Общие ограничения:

- Использовать только `npm`.
- Не запускать dev- или preview-сервер без явного разрешения владельца.
- После каждой исполнительной группы запускать `npm run lint` и `npm run typecheck`.
- Запускать `npm run build` после изменений зависимости, серверного слоя или архитектуры общих компонентов.
- Не менять JSON-контракты админки и публичных API без необходимости.
- Не переносить админку в Nuxt и не затрагивать маршруты `/admin`, `/api/auth/*` и `/api/admin/*`.

## 1. ADM-001 | Перетаскивание во всех существующих редакторах порядка

**Статус:** `done`

### Проблема

Панели «Порядок и видимость» используют две колонки и отдельные кнопки со стрелками. При большом количестве секций перестановка занимает много времени, а близко расположенные стрелки повышают риск переместить не тот блок.

Стрелки также используются в редакторе этапов и в галерее компании. Логика перестановки продублирована в нескольких view-файлах админки.

### Найденная причина

Класс `.editor-visibility-grid` задаёт две колонки. Каждый редактор отдельно обрабатывает нажатия `up` и `down`, переставляет DOM-элементы и синхронизирует скрытое JSON-поле.

Текущие поверхности со стрелками:

- главная страница;
- страницы предпринимателей, компаний и блога;
- страница «Стать героем»;
- редактор статьи;
- редактор предпринимателя;
- редактор компании;
- редактор этапов;
- галерея компании.

### Решение

- Перевести панели порядка на одну колонку на всех разрешениях.
- Добавить каждой строке отдельную drag-ручку.
- Удалить визуальные кнопки `up` и `down` после подключения перетаскивания.
- Вынести настройку сортировки в общий модуль `src/admin/lib/sortableList.ts`.
- Использовать `sortablejs` для mouse- и touch-перетаскивания. Установить пакет только через `npm install`.
- После каждого перемещения вызывать существующую синхронизацию hidden JSON, нумерации и autosave.
- Добавить drag-ручке клавиатурное управление, чтобы порядок оставался доступным без мыши.
- Не начинать перетаскивание при взаимодействии с checkbox, input, textarea, select и кнопкой удаления.

### Границы

Числовое поле `sortOrder` у карточек аудитории не входит в эту задачу. Фиксированные select-слоты популярных статей и связанных материалов также не считаются редакторами со стрелками.

### Файлы

- `package.json`
- `package-lock.json`
- `src/admin/lib/sortableList.ts` — новый файл
- `src/admin/styles/admin.css`
- `src/admin/views/home.ts`
- `src/admin/views/pageEditors.ts`
- `src/admin/views/shootingPageEditor.ts`
- `src/admin/views/articles.ts`
- `src/admin/views/entrepreneurs.ts`
- `src/admin/views/businesses.ts`
- `src/admin/views/stages.ts`

### Проверка

- Все панели порядка состоят из одной колонки.
- Drag работает мышью и через touch-ручку.
- Checkbox переключается без случайного drag.
- Порядок сохраняется после перезагрузки страницы редактора.
- Динамически добавленные story-секции, этапы и фотографии также перетаскиваются.
- `npm run lint`, `npm run typecheck` и `npm run build` проходят.

## 2. SHARED-001 | Подключить соцсети футера к настройкам

**Статус:** `done`

### Проблема

Администратор заполняет поля `SOCIAL_*` на production, но футер не меняется. Второй ряд ссылок не появляется.

### Найденная причина

Новый `SiteFooter` использует статический массив из Telegram, VK и YouTube. Компонент не читает сохранённые `SiteSetting`, хотя сетка футера уже содержит три desktop-колонки и автоматически поддерживает второй ряд.

Legacy-футер выводил шесть текстовых ссылок в следующем порядке:

1. Telegram
2. Instagram
3. VK
4. YouTube
5. Pinterest
6. Dzen

### Решение

- Добавить типизированный публичный endpoint данных футера, например `server/api/site-footer.get.ts`.
- Читать только разрешённые публичные ключи. Не возвращать полный объект настроек, потому что в нём находятся Telegram bot token, chat ID, admin email и другие закрытые значения.
- Преобразовывать шесть заполненных полей в массив `{ label, href }` в legacy-порядке.
- Передавать массив в `SiteFooter` через общий layout.
- Не выводить ссылку, если соответствующее поле пустое.
- Сохранить сетку `lg:grid-cols-3`: при четырёх–шести заполненных значениях браузер создаёт второй ряд автоматически.
- Использовать текущие статические три ссылки как безопасный fallback только при ошибке загрузки публичных настроек.

После выкладки исправления уже заполненные production-значения должны появиться без повторного ввода.

### Группировка `/admin/settings`

Плоский список полей нужно разделить обычными заголовками и пояснениями.

Секция «Социальные сети в футере» содержит:

- Telegram
- Instagram
- VK
- YouTube
- Pinterest
- Dzen

Под заголовком нужно добавить пояснение: «Заполненные ссылки отображаются в футере справа, по три в строке».

Секция «Прочие социальные ссылки» содержит:

- X
- WhatsApp

Секция «Интеграция Telegram» содержит:

- Telegram bot token
- Telegram chat ID

Так публичную ссылку Telegram нельзя случайно перепутать с настройками бота.

### Границы

- X и WhatsApp не добавляются в двухрядную сетку футера в рамках этой задачи.
- Задача не меняет нижнюю строку `ИП Батагов А.А. / Пошта Почта / Политика конф-ти`; она вынесена в SHARED-004.
- Миграция БД не требуется: значения уже хранятся в `SiteSetting`.

### Файлы

- `src/admin/views/settings.ts`
- `server/api/site-footer.get.ts` — новый файл
- `server/utils/site-settings.ts`
- `app/shared/types/site-footer.ts` — новый файл
- `app/shared/social.ts`
- `app/shared/ui/layout/LayoutDefault.vue`
- `app/shared/ui/footer/SiteFooter.vue`

### Проверка

- Существующие production-значения появляются после выкладки без повторного сохранения.
- Три заполненных поля дают один ряд.
- Шесть заполненных полей дают два ряда по три ссылки.
- Пустые поля не создают пустые элементы.
- Публичный endpoint не возвращает bot token, chat ID и другие закрытые настройки.
- `npm run lint`, `npm run typecheck` и `npm run build` проходят.

## 3. SHARED-002 | Вынести дополнительные секции в shared UI

**Статус:** `done`

### Проблема

Компоненты `EntrepreneurStoryVariant01–04` больше не принадлежат только предпринимателям. Страницы компаний используют тот же renderer и напрямую импортируют Portrait-вариант для блока «О компании».

Текущие имена скрывают фактическую область переиспользования. `EntrepreneurStorySection` также пересылает произвольные attrs в выбранный вариант, поэтому props кнопки могут попасть HTML-атрибутами в неподходящую секцию.

### Решение

Создать общую структуру:

```text
app/shared/ui/additional-sections/
├── AdditionalSection.vue
├── AdditionalSectionBiography.vue
├── AdditionalSectionAccent.vue
├── AdditionalSectionPortrait.vue
└── AdditionalSectionWide.vue

app/shared/types/additional-section.ts
```

Соответствие компонентов:

| Текущий компонент | Новый компонент |
|---|---|
| `EntrepreneurStorySection` | `AdditionalSection` |
| `EntrepreneurStoryVariant01` | `AdditionalSectionBiography` |
| `EntrepreneurStoryVariant02` | `AdditionalSectionAccent` |
| `EntrepreneurStoryVariant03` | `AdditionalSectionPortrait` |
| `EntrepreneurStoryVariant04` | `AdditionalSectionWide` |

### Карта компонентов

- `AdditionalSection.vue` принимает общий discriminated union и выбирает один визуальный компонент по `section.type`.
- `AdditionalSectionBiography.vue` отображает биографический заголовок, тексты, изображение и CTA.
- `AdditionalSectionAccent.vue` отображает акцентную текстовую секцию.
- `AdditionalSectionPortrait.vue` отображает текст, CTA и вертикальное изображение.
- `AdditionalSectionWide.vue` отображает текст, CTA и широкое изображение до выполнения SHARED-003.

Каждый компонент получает явные typed props. `AdditionalSection.vue` не использует `useAttrs()` для неявной передачи бизнес-параметров.

### Типы и сервер

- Перенести union `EntrepreneurStorySection` в `app/shared/types/additional-section.ts` и переименовать в `AdditionalSection`.
- Переименовать variant-интерфейсы в `AdditionalSectionBiography`, `AdditionalSectionAccent`, `AdditionalSectionPortrait` и `AdditionalSectionWide` или добавить суффикс `Data`, если он устраняет конфликт с именами компонентов.
- Обновить импорты админки, Nuxt-компонентов и серверных schemas.
- Оставить `server/utils/entrepreneur-story-sections.ts` на месте: утилита по-прежнему нормализует legacy-поля конкретно предпринимателя, но возвращает общий тип.
- Сохранить текущие JSON-данные, discriminator `type` и shape API без изменений.

### Границы

- Эта задача не меняет внешний вид секций.
- Высота Portrait-фото и кнопка Wide меняются только в SHARED-003.
- Задача не переименовывает поля Prisma `storySections` и `sectionOrder`, чтобы не создавать ненужную миграцию.
- Не создавать barrel `index.ts` в auto-imported каталогах.

### Файлы

- `app/shared/types/additional-section.ts` — новый файл
- `app/shared/ui/additional-sections/AdditionalSection.vue` — новый файл
- `app/shared/ui/additional-sections/AdditionalSectionBiography.vue` — новый файл
- `app/shared/ui/additional-sections/AdditionalSectionAccent.vue` — новый файл
- `app/shared/ui/additional-sections/AdditionalSectionPortrait.vue` — новый файл
- `app/shared/ui/additional-sections/AdditionalSectionWide.vue` — новый файл
- `app/features/entrepreneurs/model/entrepreneur.types.ts`
- `app/features/entrepreneurs/ui/EntrepreneurProfilePage.vue`
- `app/features/companies/ui/CompanyProfilePage.vue`
- `server/utils/entrepreneur-story-sections.ts`
- `server/utils/admin-schemas.ts`
- `server/api/companies/[slug].get.ts`
- `src/admin/api.ts`
- `src/admin/views/entrepreneurs.ts`
- `src/admin/views/businesses.ts`
- старые `EntrepreneurStorySection.vue` и `EntrepreneurStoryVariant01–04.vue` удаляются после перевода всех импортов

### Проверка

- Все четыре типа отображаются на страницах предпринимателей и компаний без визуальных изменений.
- Блок «О компании» использует новый `AdditionalSectionPortrait`.
- Сохранённые production story sections продолжают проходить schemas и отображаться.

- `npm run lint`, `npm run typecheck` и `npm run build` проходят.

## 4. CMP-001 | Уменьшить верхний отступ секции «Основатель»

Секция `CompanyFounderSection` использует `lg:pt-[380px]`. Отступ значительно превышает вертикальный ритм соседних контентных секций.

## 6. LB-001 | Поднять плашку заголовка карточки «Места»

**Статус:** `done`

### Проблема

Плашка с названием места находится внутри media-контейнера с `overflow-hidden`. При отрицательном `top` контейнер обрезает выступающую часть заголовка.

Текущая плашка:

```html
<h3 class="absolute left-0 top-0 z-1 max-w-[90%] bg-accent px-2 py-1.5 text-lg font-bold uppercase leading-none tracking-wide text-text-on-accent">
```

### Решение

- Переместить `h3` из внутреннего `<div class="... overflow-hidden">` в корневой `NuxtLink`.
- Сохранить `NuxtLink` как `relative`-контейнер позиционирования.
- Заменить `top-0` на `-top-2.5`, что соответствует `top: -10px`.
- Сохранить плашку поверх изображения и hover-overlay через текущий z-index.
- Не добавлять `overflow-hidden` корневой ссылке.
- Проверить mobile slider отдельно: его горизонтальный scroll-контейнер может обрезать вертикальный отрицательный overflow. При подтверждении добавить track-контейнеру локальный верхний padding, не меняя высоту самой карточки.

### Границы

- Изменение применяется только к карточкам секции «Места» на главной странице.
- Размер, цвет, текст, изображение, описание и hover-эффект карточки не меняются.
- Карточка остаётся полноценным `NuxtLink`; отдельная ссылка для заголовка не создаётся.

### Файлы

- `app/features/landing/ui/sections/components/LandingPlaceCard.vue`
- `app/features/landing/ui/slider/LandingSlider.vue` — только если mobile scroll-контейнер обрезает поднятую плашку

### Проверка

- Плашка выступает над верхней границей карточки примерно на 10 px.
- Плашка не обрезается внутренним media-контейнером.
- Заголовок остаётся видимым поверх изображения и hover-состояния.
- Desktop grid и mobile slider не обрезают отрицательный vertical overflow.
- `npm run lint` и `npm run typecheck` проходят.

## 7. SHARED-003 | Изменить Portrait- и Wide-дополнительные секции

**Статус:** `done`

**Зависимость:** сначала выполнить SHARED-002.

### 7.1. Portrait — ограничить вертикальное фото

Сейчас изображение использует `w-full object-cover` без ограничения высоты. Высота зависит от исходных пропорций файла, поэтому фотография растягивает всю секцию и создаёт большие расстояния между текстовыми блоками.

Решение:

- На desktop задать изображению `lg:h-[800px]`.
- Использовать `object-contain object-right`, чтобы изображение сохраняло пропорции и прижималось вправо.
- На mobile не задавать фиксированную высоту 800 px; сохранить адаптивное изображение.
- Не менять grid-пропорции 60/40 и тексты секции.

### 7.2. Wide — удалить кнопку

Кнопка «Смотреть интервью» или «Читать подробнее» перегружает широкую композицию и не нужна для этого типа дополнительной секции.

Решение:

- Удалить `ButtonLink` из `AdditionalSectionWide.vue`.
- Удалить импорт `ButtonLink`, `buttonHref`, `buttonLabel` и их defaults из Wide-компонента.
- Перестроить локальные вертикальные отступы так, чтобы фотография сохраняла ожидаемое положение после удаления кнопки.
- Не удалять кнопки из Biography и Portrait.
- Обновить `AdditionalSection.vue`, чтобы он не передавал button props в Wide-компонент.

### Файлы

- `app/shared/ui/additional-sections/AdditionalSection.vue`
- `app/shared/ui/additional-sections/AdditionalSectionPortrait.vue`
- `app/shared/ui/additional-sections/AdditionalSectionWide.vue`
- `app/features/companies/ui/CompanyProfilePage.vue` — только для удаления ставших ненужными Wide button props, если они останутся после SHARED-002

### Проверка

- Portrait-фото на desktop имеет высоту 800 px, сохраняет пропорции и прижато вправо.
- Portrait-фото на mobile не создаёт секцию высотой 800 px.
- В Wide-секции нет CTA-кнопки у предпринимателей и компаний.
- Biography- и Portrait-кнопки продолжают работать.
- `npm run lint` и `npm run typecheck` проходят.

## 8. SHARED-004 | Сделать нижнюю строку футера редактируемой

**Статус:** `done`

### Решение

- Добавить в `/admin/settings` отдельную секцию «Нижняя строка футера».
- Хранить массив объектов в существующем `SiteSetting`, например под ключом `FOOTER_META_ITEMS`.
- Использовать структуру `{ text: string, href: string }`, где `text` обязателен, а `href` может быть пустым.
- Добавить создание, удаление и drag-and-drop-сортировку строк.
- Проверять JSON на сервере и разрешать только безопасные внутренние пути и протоколы `http:`, `https:`, `mailto:` и `tel:`.
- Расширить публичный endpoint футера и передавать нормализованный массив в `SiteFooter`.
- Рендерить обычный текст при пустом `href`.
- Рендерить `NuxtLink` для внутреннего пути и `<a>` для внешней ссылки.

Начальное fallback-значение:

```json
[
  { "text": "ИП Батагов А.А.", "href": "" },
  { "text": "Пошта Почта", "href": "" },
  { "text": "Политика конф-ти", "href": "" }
]
```

### Границы

- Поле `FOOTER_TEXT` не переиспользуется: оно представляет legacy-строку и не описывает массив объектов.
- Миграция Prisma не требуется, потому что `SiteSetting` уже хранит произвольные строковые значения.
- Задача не меняет основные ссылки страниц, социальные ссылки и CTA футера.
- Текст обязателен для каждой сохранённой строки; пустые строки не попадают в публичный ответ.

### Проверка

- Администратор может добавить, удалить и перетащить элемент нижней строки.
- Строка без текста не сохраняется.
- Элемент без ссылки отображается как текст.
- Внутренняя ссылка работает без полной перезагрузки страницы.
- Внешняя ссылка получает корректный `<a>` и безопасный `rel`.
- При отсутствии нового setting футер показывает три текущих fallback-элемента.
- `npm run lint`, `npm run typecheck` и `npm run build` проходят.

## Исключено из fixesDesign04

Исходная задача про поддержку `\n` в заголовках удалена за ненадобностью. Поля заголовков дополнительных секций уже являются `textarea`, а целевые Portrait- и Wide-компоненты обрабатывают обычный перенос, введённый клавишей Enter. Литеральная последовательность `\n` не добавляется и не требует отдельной реализации.

## Definition of done

Волна `fixesDesign04` считается завершённой, когда:

- каждая утверждённая задача имеет статус `done` или `verified`;
- drag-and-drop сохраняет существующие значения порядка без изменения серверных контрактов;
- дополнительные секции используют общий shared-каталог и общий тип;
- production-настройки соцсетей реально управляют футером;
- локальные визуальные изменения не ломают mobile-композиции;
- нижняя строка футера редактируется без миграции БД;
- `npm run lint`, `npm run typecheck` и требуемые `npm run build` проходят;
- все непройденные проверки явно указаны в итоговом отчёте.
