# fixesDesign02 — Беклог правок от дизайнера

Назначение: накопительный документ замечаний дизайнера по новому публичному слою (Nuxt 4) и админке. Каждая задача — «Проблема» + «Предполагаемое решение» с явным указанием файлов.

## Правила работы

Статусы (проставляет владелец проекта):

- `new` — занесено, решение согласовано в черновике, можно исполнять после одобрения
- `approved` — одобрено владельцем, назначено в работу
- `in-progress` — прямо сейчас правится
- `done` — исправлено, ждёт проверки
- `verified` — проверено владельцем/дизайнером
- `hand-fixed` — владелец сам поправил по этой задаче; агент обязан учитывать эту правку и не переписывать её поверх
- `waiting-design` — задача ждёт уточнения от дизайнера/владельца; к работе НЕ приступать

Правила для агентов (обязательные):

- Править ТОЛЬКО файлы, перечисленные в задаче. Код вне задачи не трогать, не рефакторить, не переформатировать.
- Не откатывать и не переписывать чужие правки и правки с меткой `hand-fixed`.
- По завершении: `npm run lint` + `npm run typecheck` (build — по запросу владельца), статус `done`, в отчёте — список изменённых файлов.

Префиксы секций: `LB-` лендинг `/`, `CMP-` компании `/companies` (+ /businesses), `ENT-` предприниматели, `BLG-` блог, `SR-` съёмка `/shooting-request`, `SHARED-` общие компоненты (header/footer/hero/карточки), `ADM-` админка.

## SHARED — общие компоненты

### SHARED-001 | Логотип в хедере: ромбик всегда, настоящий лого — после mount/скролла

**Статус:** `done`

**Проблема:** на десктопе на некоторых страницах нельзя вернуться на главную — логотипа нет. Две причины:
1. `logoVisible` глобально `false` по умолчанию (`useSiteHeader.ts:2`); на страницах без скролл-логики (`/companies`, `/blog`, `/entrepreneurs` и пр.) логотип так и остаётся скрытым на desktop.
2. На `/` и `/shooting-request` логотип появляется только после скролла (управление из `LandingPage.vue` / `ShootingRequestPage.vue`), до этого в углу пусто, кликнуть некуда. При первичной отрисовке это тоже выглядит как баг.

**Предполагаемое решение:**
- `SiteHeader.vue`: использовать отдельную копию ромбика `const loadingLogoImage = '/images/LogoPlaceholder.svg'`. Если `logoVisible === false` — показывать ромбик в том же NuxtLink-контейнере (кликабельный, размеры как у лого: `h-9 sm:h-10 lg:h-11 object-contain`). Если `true` — настоящий `SiteLogo` с быстрой анимацией появления (opacity/translate ~120–150ms).
- `useSiteHeader.ts`: оставить дефолт `false` (в SSR на лендинге ромбик — это нужно), добавить список страниц со скролл-логикой `['/', '/shooting-request']` и функцию синхронизации состояния по текущему маршруту.
- `LayoutDefault.vue`: отслеживать изменение маршрута. Для страниц вне списка скролл-логики устанавливать `logoVisible = true`; при переходе на `/` или `/shooting-request` возвращать управление соответствующей странице. Это должно работать и при переходах внутри уже смонтированного layout.
- Скролл-логику лендинга и `/shooting-request` не трогать: до появления лого виден кликабельный ромбик.
- Mobile не менять: там логотип и сейчас виден всегда (классы `lg:invisible`/`lg:opacity-*` применяются только на desktop).

**Файлы:**
- `app/shared/ui/header/SiteHeader.vue`
- `app/shared/ui/header/useSiteHeader.ts`
- `app/shared/ui/layout/LayoutDefault.vue`
- `public/images/LogoPlaceholder.svg`

### SHARED-002 | Висящие предлоги в заголовках: неразрывные пробелы (`text-balance` не решает)

**Статус:** `done`

**Проблема:** при автоматическом переносе строка может заканчиваться предлогом, напр. «МЕДИЙНОЕ МЕСТО В СБС» — «В СБС» переносится на новую строку. Это нарушает стандарт журнальной вёрстки. Ни `text-wrap: balance`, ни `text-wrap: pretty` правило «предлог не в конце строки» не гарантируют.

**Предполагаемое решение:**
- Новая утилита `app/shared/lib/typography.ts`: `protectPrepositions(text)` — regex-замена пробела после перечисленных в задаче одно- и двухбуквенных предлогов/союзов (`В, К, И, У, О, С, На, За, По, От, До, Не, А` и т.п.) на неразрывный (`\u00A0`). Список из задачи является рабочим списком для реализации.
- Применять к обычным текстовым заголовкам и подписям из API через computed в конкретных компонентах. Не применять к HTML-rich-text контенту статей. Дополнительный парсинг HTML или произвольной разметки не нужен.
- Дополнительно `text-wrap: balance` (класс `text-balance`) на общие заголовки — бесплатное улучшение переносов.
- Данные в админке не меняются — правка только при отображении.

**Файлы:**
- `app/shared/lib/typography.ts` — новая утилита
- `app/shared/ui/page/SectionTitle.vue` + заголовки секций (применение)

### SHARED-004 | Карта: несколько точек (заведения, франшизы) — массив координат

**Предполагаемое решение (без подписей у точек, только красные точки):**

- `server/utils/yandex-map.ts`: сразу перейти на финальный формат `MapCoordinates[]` и парсить поле построчно. Поддерживать нужно только новый согласованный формат списка координат; legacy iframe/URL-форматы сохранять не требуется.
- `YandexMap.vue`: `pt` склеивать через `~` для нескольких точек (виджет поддерживает: `pt=lon1,lat1,pm2rdm~lon2,lat2,pm2rdm`); центрирование по первой точке или вычисление центра bbox.
- `CompanyAddressesSection.vue`: принимать массив координат и не рендерить карту при пустом массиве.
- `server/api/companies/[slug].get.ts`: передавать массив координат из нового парсера.
- `app/features/companies/model/companies-page.types.ts`: заменить `MapCoordinates | null` на `MapCoordinates[]`.

### SHARED-009 | Единый стиль CTA-кнопок: начертание, стрелка, hover (белый фон + красный текст)

**Статус:** `done` (этап 1)

**Проблема:** дизайнер: «кнопки все в едином стиле, одним шрифтом и одним начертанием; у всех красных кнопок при наведении подсветка — белый фон, красный текст». Сейчас (см. разбор в LB-002, задача удалена) на сайте три разных языка кнопок:

**Уточнение владельца после визуальной проверки:** «Узнать подробнее» в `LandingContactForm` — отдельное исключение: кнопка остаётся белой и без стрелки.

**Предполагаемое решение:**

- `LandingContactForm.vue` «Узнать подробнее» не переводить на дефолтный `ButtonLink`: сохранить белый `NuxtLink` без стрелки.
- Точные параметры (трекинг, размеры, вариант стрелки) зафиксировать по макету при исполнении.

### BLG-005 | `/blog/SLUG`: дата не высвечивается (нет fallback на createdAt)

### BLG-006 | `/blog/SLUG`: текст статьи должен идти по ширине фото + избавиться от самовольных суженных контейнеров

**Статус:** `done` (этап 2)

**Проблема:**
1. cover-фото занимает весь контейнер `max-w-[1440px]` (`BlogDetailPage.vue:34`), а текстовая колонка — только `max-w-[980px]` (строка 65). На десктопе текст выглядит узким столбиком посреди широкого фото; дизайнер: «текст должен идти по ширине фото».
2. **Самовольные контейнеры:** общий паттерн сайта — `max-w-[1920px]` (хедер `SiteHeader.vue:69`, футер, `LayoutMaster.vue:3`, все секции страниц, включая остальные секции блога). В `BlogDetailPage.vue` три внутренних контейнера сужены вручную: cover `max-w-[1440px]` (строка 34), content `max-w-[980px]` (строка 65), secondary `max-w-[1440px]` (строка 78). В legacy-вёрстке было `width: min(1920px, calc(100% - 80px))` (`migration_old/css/main.css:9161`) — тоже 1920px. Сужение появилось при переносе самовольно, таких контейнеров быть не должно.

**Предполагаемое решение:**
- Избавиться от самовольных сужений: cover и secondary привести к `max-w-[1920px]` (единый контейнер с остальным сайтом).
- Контент статьи (`content`, строка 65) также привести к `max-w-[1920px]` — «текст идёт по ширине фото», заодно выравнивается с cover-фото в одном контейнере. Читаемость при необходимости решается внутренними ограничениями (например `max-w-*` на самих абзацах/Typography), а не сужением контейнера.
- Точную внутреннюю ширину текста при необходимости зафиксировать при проверке с дизайнером.

**Файлы:**
- `app/features/blog/ui/BlogDetailPage.vue`

### ADM-001 | `/admin/businesses`: достижения — селектор готовых значков вместо ручной загрузки

**Статус:** `done` (этап 3; решение подтверждено дизайнером 09.08.2026: «да»)

**Проблема (формулировка дизайнера):** «в достижениях к месту нельзя переключать значки, те что сбоку — надо чтоб были те, что переключать можно». На фронте у карточек достижений всегда статичные `reward-white.svg` / `reward-black.svg` (`CompanyAwardsSection.vue:41-44`), а в админке (`renderBusinessAwardRow`, `businesses.ts:889-913`) у карточки есть только поле «загрузить иконку» (URL/файл) — готовых значков-переключателей нет.

**Вопрос владельца дизайнеру (пересказан дословно):** «По достижениям в админке: правильно понимаю, что речь именно про значки в карточках достижений? Нужно сделать выбор готовой иконки из нескольких вариантов, чтобы её можно было переключать, а не загружать вручную?» — ответ дизайнера: **«да»**.

**Предполагаемое решение (зафиксировано):** в карточке достижения сделать селектор готовых значков (пресет: `reward-white`, `reward-black` и др.), чтобы «переключать» значки без загрузки файла; значение подставляется в поле иконки карточки. На фронте убрать статичный дуэт значков, если селектор покрывает их.

**Файлы:**
- `src/admin/views/businesses.ts` (renderBusinessAwardRow / attachBusinessAwards)
- `app/features/companies/ui/profile/CompanyAwardsSection.vue`
